# Contributing to Options Paper

Thanks for your interest in improving this skill.

**This repo is not actively maintained.** It was published as a one-time release, not something
I'm committed to reviewing or updating on an ongoing basis. Issues and PRs may sit unanswered for
a long time, or indefinitely. If you need changes, forking is likely faster than waiting on a
response here.

## What's most useful

- A refinement to the document structure that makes options papers clearer or more decision-ready
- A fix to `build_options_paper.py` for a Word template edge case it currently mishandles
- A second worked example (fictional or genuinely your own) showing the format in a different domain
- Improvements to the sceptic-pass checklist

## How to contribute

1. Fork the repository
2. Create a branch (`git checkout -b improvement/your-change`)
3. Make your changes
4. Open a pull request with a clear description of what you changed and why

## What to avoid

- Changes specific to one organisation's branding or workflow — keep it general
- Adding dependencies to `build_options_paper.py` — it works from the standard library only, and
  should stay that way
- Real internal documents or quotes as examples — keep worked examples fictional or clearly your
  own to publish

## Questions?

Open an issue if you like, but see the note above — don't expect a quick reply.
